## 1. 设计目标

| 目标 | 具体指标 |
| --- | --- |
| 可扩展 | 核心模块解耦，替换爬虫 / 推送 / 支付等外部能力不影响主业务 |
| 可维护 | 统一技术栈（Python 后端 / TS 前端），分层清晰，单元测试覆盖 ≥ 70% |
| 高性能 | 单节点支撑 500 QPS，标讯全表 500 万行级 |
| 安全合规 | HTTPS、JWT、RBAC、SQL 注入防护、XSS 过滤、接口限流 |

## 5. 后端三层架构

```
HTTP 请求
  │
  ▼
[API 路由层]   参数校验（Pydantic Schema）、鉴权、依赖注入
  │
  ▼
[Service 服务层]  核心业务逻辑、事务、跨表操作、去重指纹、匹配算法
  │
  ▼
[Data 数据层]  SQLAlchemy Model → MySQL / Redis / OSS
```

**依赖方向**：`API → Service → Model`，上层可以 import 下层，下层不能反向。

## 6. 核心数据流

### 6.1 爬虫数据流

```
Crawl Task (Celery)
  │
  ▼
读取 bid_source 配置（interval_minutes < 当前时间 - last_crawl_at）
  │
  ▼
httpx 请求列表页（带 headers / 代理 / 重试）
  │
  ▼
BeautifulSoup / lxml 解析 → 抽取详情 URL 列表
  │
  ▼
并发请求详情页（ThreadPool 10 线程）
  │
  ▼
按 field_rules 抽取字段 → 清洗 HTML → 生成 content_text
  │
  ▼
生成 dedup_key = sha1(title + region_code + publish_time_text)
  │
  ├─ 已存在 → 跳过
  └─ 不存在 → INSERT bid_info(status=0)
  │
  ▼
更新 source.last_crawl_at
```

### 6.2 订阅推送数据流

```
Celery Beat 每日 08:00 触发 push_daily_subscriptions
  │
  ▼
查询所有 frequency=daily 且 status=1 的订阅
  │
  ▼
foreach 订阅:
  │
  ▼
  查询 publish_time > 昨天 08:00 且 status=1 的标讯
  │  并按 region_code / notice_type_id 过滤
  │
  ▼
  关键词匹配（空格 / 逗号拆分为 AND 组，组内 OR）
  │
  ▼
  命中数量 > 0 ?
  ├─ 是 → 合并 HTML 邮件 → SMTP 发送 → 写 push_record
  └─ 否 → 跳过（避免空邮件骚扰）
  │
  ▼
更新 subscribe.last_push_at
```

### 6.3 会员订单数据流

```
前台: POST /api/v1/member-orders (package_id)
  │
  ▼
后端: 查询套餐 → 创建订单 (order_no, amount, status=0)
  │
  ▼
返回订单号 → 前端调起微信 / 支付宝支付
  │
  ▼
第三方回调 → POST /api/v1/member-orders/callback
  │
  ▼
校验签名 → 更新订单 (status=1, pay_time, trade_no)
  │
  ▼
计算会员有效期:
  新会员: today ~ today + duration_days
  已有会员: 保留原 end_date 或取较大值再加 duration_days
  │
  ▼
更新 member_order.start_date / end_date
  │
  ▼
会员权益即时生效（查询时动态计算有效期）
```

## 7. 安全设计要点

| 层 | 措施 |
| --- | --- |
| 传输 | 全站 HTTPS；API 强制 HSTS (max-age=31536000; includeSubDomains) |
| 鉴权 | JWT Bearer Token，header `Authorization: Bearer <token>`；刷新策略（预留） |
| 密码 | bcrypt (cost=12)；登录失败限流（Redis 计数器，5 次 / 分钟 / IP） |
| 接口 | 后端路由按 role / permission 加 decorator；前端菜单按角色动态渲染 |
| 注入 | SQLAlchemy ORM 参数化；禁止拼接 SQL |
| XSS | 后台富文本用白名单标签库净化；前台 `v-html` 内容后端统一 escape |
| 限流 | Redis + 令牌桶，默认 100 req/s / IP；登录接口更严 |
| 合规 | 所有爬虫接口标注来源；底部放置用户协议、隐私政策、版权声明 |
| 日志 | 登录日志、操作日志、爬虫日志分离存储；敏感字段脱敏 |

## 9. 关键中间件参数

### 9.1 MySQL

```ini
[mysqld]
innodb_buffer_pool_size = 2G           # 2C4G 机器给 50%
innodb_log_file_size = 256M
max_connections = 500
slow_query_log = ON
slow_query_log_file = /var/log/mysql/slow.log
long_query_time = 2
character-set-server = utf8mb4
collation-server = utf8mb4_unicode_ci
```

### 9.2 Redis

```conf
# redis.conf
maxmemory 512mb
maxmemory-policy allkeys-lru
save ""                  # 用 RDB + AOF 混合
appendonly yes
appendfsync everysec
```

### 9.3 Celery

| 项 | 值 |
| --- | --- |
| broker | `redis://127.0.0.1:6379/1` |
| backend | `redis://127.0.0.1:6379/2` |
| worker_concurrency | 4 |
| task_acks_late | True |
| result_expires | 3600 |

### 9.4 Uvicorn

| 环境 | workers | 说明 |
| --- | --- | --- |
| dev | 1 + reload | 自动热重载 |
| prod | `min(cpu_count, 4)` | I/O 密集应用 4-8 够用 |

## 10. 目录与命名约定

| 对象 | 风格 | 示例 |
| --- | --- | --- |
| Python 包 / 模块 | snake_case | `app.services.crawl_service` |
| Python 类 | PascalCase | `class BidService:` |
| 数据库表 | snake_case | `bid_info`, `member_order` |
| 字段 | snake_case | `publish_time`, `dedup_key` |
| 路由路径 | 小写下划线，复数资源 | `/api/v1/bids`, `/api/v1/bid-sources` |
| API 资源 | `/<resource>` 表资源 + 嵌套动作 | `POST /bids/{id}/audit` |
| 环境变量 | UPPER_SNAKE | `DB_HOST`, `OSS_ENDPOINT` |
| Git 分支 | `feat/*`, `fix/*`, `hotfix/*`, `main` | `feat/crawl-scrapy` |
