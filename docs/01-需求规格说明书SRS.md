# 标讯信息管理系统 - 需求规格说明书（SRS）

> 版本：v0.2 · 状态：评审冻结 · 日期：2026-11-20（v0.2 变更记录见文末）

---

## 1. 文档目的

本文档对"标讯信息管理系统"的功能性需求、非功能性需求、角色与约束进行结构化描述，作为后续设计、开发、测试与验收的一致依据。

## 2. 系统定位

**标讯资讯系统** —— 面向企业用户的招标公告采集、展示、检索、订阅与会员服务平台。

| 项 | 说明 |
| --- | --- |
| 核心价值 | 一站式聚合全国公共资源交易平台、政府采购网、行业招标平台的公告，让企业采购人员 / 投标方高效获取标讯 |
| 用户形态 | PC 官网 + H5 + 管理后台 |
| 部署形态 | 单机 / 轻量集群（≤ 3 节点） |
| 合规要求 | 采集公共资源公告需标注来源、遵守 robots 协议；官网需放置用户协议 & 隐私政策 |

> **非本文档范围**：在线发标、电子开标评标、CA 数字证书 —— 业务版功能不在本期交付中。

## 3. 角色与权限概览

| 角色 | 典型使用场景 | 关键能力 |
| --- | --- | --- |
| 超级管理员 admin | 系统配置、权限分配、全局管控 | 全部权限 |
| 内容编辑 editor | 标讯录入、编辑、下架、附件上传 | 标讯 CRUD、附件管理 |
| 审核员 auditor | 对采集 / 录入的标讯做审核发布 | 审核通过 / 驳回 |
| 运营员 ops | 采集源配置、会员套餐、订阅运营 | 采集源 / 套餐 / 订单管理 |
| 企业会员 member | 检索标讯、订阅关键词、查看联系方式、批量导出 | 搜索、订阅、会员专属功能 |
| 普通访客 guest | 浏览公开标讯列表与详情 | 浏览、基础检索 |

## 4. 功能性需求

### 4.1 标讯采集（Crawl）

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| CA-01 | 支持配置多个采集源（爬虫 / 开放接口 / 手动 / Excel） | P0 |
| CA-02 | 每个采集源可配置列表页 URL、字段提取规则、请求间隔、自定义 Header | P0 |
| CA-03 | 支持手动触发单次采集 & 按 Cron 周期自动采集 | P0 |
| CA-04 | 自动识别重复公告（基于 `dedup_key = sha1(title + region + publish_time_text)`），重复则跳过入库 | P0 |
| CA-05 | 采集失败时记录日志并按指数退避重试（最多 3 次） | P1 |
| CA-06 | 清洗 HTML 正文，抽纯文本存入 `content_text` 用于全文检索 | P1 |
| CA-07 | 采集到的标讯默认状态为"待审核"，编辑或运营可快速审核发布 | P0 |

> 合规提示：爬虫必须遵守目标站点 robots.txt；采集政府公开信息需在网站底部声明来源并标注"仅供参考"。

## 5. 非功能性需求

### 5.1 性能

| 指标 | 目标 |
| --- | --- |
| 前台首页 / 列表接口 P95 响应时间 | ≤ 300 ms |
| 详情接口 P95 | ≤ 500 ms |
| 爬虫并发采集源数 | ≥ 10 |
| 订阅推送并发 | ≥ 50 封 / 分钟 |
| 单表数据量容量 | `bid_info` ≥ 500 万行 |

### 5.2 可用性

- 核心 API 可用率 ≥ 99.5%
- 数据库每日自动备份；保留 7 天日增量 + 4 周全量
- OSS 对象存储多副本，附件不丢失

### 5.3 安全

| 项 | 要求 |
| --- | --- |
| 密码存储 | bcrypt，cost ≥ 10 |
| 传输 | 全站 HTTPS；API 强制 HSTS |
| 鉴权 | JWT + 黑名单（可选） |
| 防攻击 | SQL 注入（ORM 参数化）、XSS（前端 CSP + 后端 HTML escape）、接口限流（Redis + 令牌桶）、CSRF（SameSite Cookie） |
| 敏感信息 | 手机号 / 邮箱在列表接口脱敏；数据库字段加密（可选） |
| 审计 | 关键操作写日志；登录日志；爬虫采集日志 |

### 5.4 可维护性

- 后端统一使用 Alembic 管理数据库迁移
- API 自动生成 Swagger 文档，路径 `/docs`
- 关键路径单元测试覆盖率 ≥ 70%
- Dockerfile + docker-compose.yaml 一键部署（后续补充）

### 5.5 兼容性

| 端 | 最低版本 |
| --- | --- |
| PC 浏览器 | Chrome 90+、Edge 90+、Firefox 88+ |
| 移动端 H5 | iOS Safari 13+、Android Chrome 88+、微信内置浏览器 |

## 6. 业务流程图

### 6.1 标讯采集 → 审核 → 发布

```
采集源配置 → 定时触发 / 手动触发 → 爬取列表页 → 抽取字段 → 清洗去重
 → 入库 (status=0 待审核) → 审核员审核
   ├─ 通过 → status=1 已发布
   └─ 驳回 → status=2 已下架 + 填写原因
```

### 6.2 用户订阅 → 推送

```
会员创建订阅 (keyword + region + frequency)
  → Celery Beat 定时触发 crawl_daily_subscriptions (8:00)
    → 查询当日新增标讯 (publish_time > 昨天 8:00)
    → 逐条匹配订阅关键词
    → 合并到订阅邮箱
    → SMTP 发送邮件
    → 写 push_record
```

### 6.3 会员购买流程

```
前台选择套餐 → 创建订单 (status=0) → 调用微信/支付宝
 → 支付成功回调 → 订单置为已支付
 → 计算有效期 (当前时间 + duration_days) → 写 member_order
 → 会员权益立即生效
```

## 8. 约束与风险

| 编号 | 约束 / 风险 | 缓解 |
| --- | --- | --- |
| R-01 | 公共资源交易平台反爬严格、改版频繁 | 优先使用官方开放 API；采集规则可视化管理；变更告警 |
| R-02 | 版权与合规风险 | 所有公告保留原文链接、来源名称、发布时间；站内检索结果不替代官方 |
| R-03 | 爬虫被封禁 | 设置合理请求间隔；使用代理池；遵守 robots.txt |
| R-04 | 推送频率过高导致邮箱被退 | 订阅命中合并邮件；单用户每日最多 3 封；失败进入降级队列 |
| R-05 | 单点 | 数据库做主从 / OSS 多副本 / API 多实例 |
