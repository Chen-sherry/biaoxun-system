**索引设计理由**：

| 查询场景 | 使用索引 |
| --- | --- |
| 前台列表默认排序：最新发布的已发布标讯 | `idx_bid_status` + 主键顺序扫描 |
| 按地区 + 时间过滤 | `idx_bid_region_pub` 覆盖 |
| 采集源去重 | `idx_dedup` 唯一 |
| 按公告类型 / 行业筛选 | 单列索引 |
| 截止时间临近提醒 | `idx_bid_deadline` |

**分区建议（数据量 > 500 万时）**：按月对 `publish_time` 做 `RANGE COLUMNS` 分区，归档表保留 2 年在线，更早迁移到冷表。

## 4. 种子数据表（测试数据）

**用途**：存放 Excel 合并后的测试数据。来源文件 `25年4-6月关键词招中标数据8.8.xlsx`，含 14 个关键词分类 sheet：

| agency_unit | VARCHAR(255) | 代理单位 |
| original_link | VARCHAR(512) | 原文链接 |
| region_full / province / city | VARCHAR | 地区三字段 + region_id |

| news_id | VARCHAR(32) | 业务主键 |
| create_time / deadline / expected_purchase_time | DATETIME | |

**唯一键**：`UNIQUE(source_keyword, news_id)` —— 防止重复导入

**业务索引**：`source_keyword`、`win_time`、`tender_time`、`city`、`procure_type`、`notice_type`、`major`(100)、`purchase_unit`(100)、`winner_unit`(100)、`stage`、`(tender_amount, win_amount)` —— 合计 11 个业务索引，覆盖后续按关键词 / 时间 / 金额 / 单位做统计与可视化的查询场景。

**数据概览（已导入）**：

| 指标 | 值 |
| --- | --- |
| 总行数 | 8,239 |
| 时间覆盖 | 2025-04-01 ~ 2025-06-30 |
| 金额范围 | 0.00 ~ 2,876,431,000.00 |
| proc_type 分布 | 中标 4,299 / 招采 3,940 |

**导入链路**：`Excel → openpyxl 逐 sheet 读 → 清洗日期 / 金额 / NULL → 生成 raw_row_hash → INSERT IGNORE 分批 500 行`

执行脚本：`backend/scripts/import_seed_excel.py`（DDL 见 `backend/sql/02-bid_info_seed.sql`）

> **与正式 `bid_info` 的关系**：`bid_info_seed` 是独立测试表，不参与正式业务流；后续爬虫正式采集的公告写入 `bid_info`。如果需要把测试数据"转正"，可以写一个字段映射脚本把 `bid_info_seed` 数据迁移到 `bid_info`，同时填充 `dedup_key` 并将状态置为 `status=1`。

## 6. 数据库安全

| 项 | 做法 |
| --- | --- |
| 账号权限 | 应用账号只给 CRUD；建表只用 root；只读账号给报表服务 |
| 密码 | `GRANT ... IDENTIFIED BY 'xxx'`；生产密码单独存 Vault / K8s Secret |
| 审计 | `audit_log` 表记录 DDL / DML 关键操作（可选） |
| 备份 | 每日 03:00 mysqldump + binlog 实时 → OSS；保留 7 天日增 + 4 周全量 |
| 加密 | 敏感字段（phone、email）AES-GCM 加密 + 密钥轮换 |
| SQL 规范 | 禁止 `SELECT *`；禁止隐式类型转换；所有条件字段建索引；大表禁止 ALTER |

## 7. 迁移策略

- 使用 Alembic 管理版本迁移：`alembic revision --autogenerate -m "add_xxx"`
- 大表 DDL 走 `pt-online-schema-change` 或 gh-ost，避免锁表
- 每次迁移先在测试环境验证 + 回滚预案

### 时间字段双保留设计理由

Excel 里每条种子行有两个时间：
- `publish_time`（正式表原字段）→ 公告发布日期
- `winner_publish_time`（新增）→ 中标成交日期

两者不必然相同：招标公告发布于 4 月，中标结果可能 5 月才出。保留两个时间才能在列表 / 筛选 / 预警中正确工作。

### 转正脚本

- dedup_key 生成：`sha1(source_keyword + news_id + title)`，种子表 `news_id` 保证跨批次唯一

### 种子表独立存在的意义

`bid_info_seed` 保持保留，用于：
1. 回看原始 Excel 数据（字段多、业务属性全）
2. 后续若需要更多字段，可从 seed 反向补到正式表
3. 爬虫新抓的数据继续进 `bid_info`（source_type=1 爬虫），和种子来源数据并存
