# 标讯系统 - 权限设计文档

> 版本：v0.1 · 2026-11-20

---

## 1. 模型

采用标准 **RBAC（Role-Based Access Control）** 模型，实体关系：

```
sys_user ──M:N── sys_role ──M:N── sys_permission
   │                   │                    │
  用户               角色               权限节点
                                        ├─ type=1  菜单（前端路由）
                                        ├─ type=2  按钮（页面内操作）
                                        └─ type=3  接口（API 路径）
```

**超级管理员**（`sys_user.is_admin=1`）跳过全部权限检查，直接放行。

## 2. 预置角色

| role.code | role.name | 说明 |
| --- | --- | --- |
| admin | 超级管理员 | 系统唯一超级角色，生产严格管控 |
| editor | 内容编辑 | 标讯录入 / 编辑 / 下架 / 附件上传 |
| auditor | 审核员 | 标讯审核通过 / 驳回 |
| ops | 运营员 | 采集源、会员套餐、订阅运营、推送管理 |
| member | 普通会员 | 前台已注册并登录的付费用户 |
| guest | 普通访客 | 未登录，仅浏览公开内容 |

> 实际生产可灵活新增角色，如 `crawler`（仅爬虫管理）、`finance`（仅订单对账）。

## 3. 权限编码规范

**格式**：`模块:资源:动作`

```
bid:info:add         标讯新增
bid:info:edit        标讯编辑
bid:info:delete      标讯删除
bid:info:audit       标讯审核
bid:attachment:upload  附件上传

source:crawl:run     手动触发采集

member:package:edit  套餐修改
member:order:view    订单查看

user:admin:manage    后台用户管理
```

| 段 | 取值示例 |
| --- | --- |
| 模块 (module) | bid / source / subscribe / member / user / setting |
| 资源 (resource) | info / attachment / package / order / role / permission |
| 动作 (action) | add / edit / delete / view / audit / publish / run / export |

## 6. 前后端鉴权实现

### 6.1 前端（管理后台）

**路由守卫**：`router/index.ts` 中 `beforeEach`

```ts
// 1. 无 token → 跳转 /login
// 2. 有 token → fetchInfo() 拉当前用户权限列表
// 3. 动态渲染菜单（过滤无权限的路由项）
```

**按钮级别**：Element Plus 指令或自定义组件

```vue
<el-button v-permission="'bid:info:audit'">审核</el-button>
```

### 6.2 后端（FastAPI）

**登录** → 返回 JWT（payload 含 `sub=user_id` + 可选 `username`）

**依赖注入保护**：

```python
# 1. 登录保护
def get_current_user(token, db): ...

# 2. 角色保护
def require_role(*codes): ...

# 3. 权限保护（后续细化）
def require_permission(code): ...
```

**全局中间件**（可选）：对每个请求校验 JWT 并把权限集合放到 `request.state.permissions`，性能更好（一次 DB 查询 + Redis 缓存）。

### 6.3 权限缓存

```
key = "user:permissions:{user_id}"
TTL = 10 min
value = Set["bid:info:add", "bid:info:edit", ...]
失效策略：角色变更 / 权限变更时主动 DEL key
```

> admin 角色不走缓存，直接放行。

## 7. 会员权益控制（业务权限，非 RBAC）

| 权益 | 免费会员 | 月度会员 | 年度会员 | 企业会员 |
| --- | --- | --- | --- | --- |
| 查看公开标讯 | ✅ | ✅ | ✅ | ✅ |
| 查看联系方式 | ❌ | ✅ | ✅ | ✅ |
| 订阅关键词数上限 | 3 | 10 | 50 | 200 |
| 下载会员专属附件 | ❌ | ✅ | ✅ | ✅ |
| 导出 Excel | ❌ | ✅ | ✅ | ✅ |
| 高级筛选（地区 + 行业 + 时间） | ❌ | ✅ | ✅ | ✅ |
| AI 智能匹配 | ❌ | ❌ | ✅ | ✅ |
| 专属客服 | ❌ | ❌ | ❌ | ✅ |

**实现方式**：后端拦截会员专属接口，查询 `member_order.end_date >= now()` 且 `member_package.level` 满足要求。

```python
def require_member(min_level: int = 2):
    def _dep(user):
        order = db.query(MemberOrder).filter(
            MemberOrder.user_id == user.id,
            MemberOrder.status == 1,
            MemberOrder.end_date >= datetime.utcnow(),
        ).order_by(MemberOrder.end_date.desc()).first()
        if not order:
            raise HTTPException(403, "请先开通会员")
        pkg = db.query(MemberPackage).get(order.package_id)
        if pkg.level < min_level:
            raise HTTPException(403, "需要更高等级会员")
        return user, order, pkg
    return _dep
```

## 8. 审计日志

| 事件 | 记录内容 |
| --- | --- |
| 登录成功 / 失败 | user_id / username / IP / User-Agent / 时间 |
| 角色变更 | 操作者 / 目标用户 / 角色变化 |
| 权限变更 | 操作者 / 角色 / 权限变化 |
| 标讯关键动作 | 录入人 / 审核人 / 下架人 / 置顶人 |
| 支付成功 | 订单号 / 金额 / 支付渠道 |
| 爬虫手动触发 | 操作人 / 采集源 / 结果 |

> 实现：`audit_log` 表 + 业务关键点埋点；或 AOP 装饰器 `@log_action("标讯审核")`。

## 9. 安全加固项

| 项 | 措施 |
| --- | --- |
| 暴力破解防护 | IP 级登录失败 5 次 / 分钟锁定 30 分钟（Redis 计数） |
| 会话劫持 | JWT 的 `sub` + 请求 IP 绑定（可选） |
| 水平越权 | 所有查询带 `user_id` 过滤，绝不只按 `id` 查 |
| 垂直越权 | 接口加角色 / 权限 decorator |
| CSRF | 全 API 使用 JWT Bearer 头，不依赖 Cookie；若有 Cookie 场景加 SameSite |
| 权限列表不泄露 | `/auth/me` 只返回角色编码，不返回具体权限节点列表（避免探测） |

## 10. 角色管理操作手册（后台）

1. 管理员创建角色 → 勾选权限节点（可多选）
2. 分配角色给用户（可一人多角色，取并集）
3. 角色变更后 5 分钟内生效（清 Redis 缓存）
4. 新增权限节点后，需手动分配给对应角色

## 11. 后续扩展

- **多租户**：`tenant_id` 加入所有业务表，角色带 `tenant_scope`
- **数据权限**：角色 `data_scope`（全部 / 本部门 / 本人）
- **字段级权限**：某些敏感字段只对特定角色可见
- **审批流**：标讯审核扩展为多级审批（editor → auditor → 运营员抽检）

### 后端拦截实现

```python
# 依赖注入层 api/deps.py
def require_permission(code: str):
    def _dep(user, db):
        if user.is_admin: return user
        # 查 Redis 缓存的权限集合
        cached = redis.get(f"user:permissions:{user.id}")
        if cached and code in cached: return user
        # ... fallback DB 查询
    return _dep
```

### 前端动态菜单
